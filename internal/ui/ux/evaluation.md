# UX 验收

任务完成、规范一致与视觉质量分别验收。构建和截图不能代替交互结果。

## 自动入口

```sh
npm ci
npm run ui:check
TZ=Asia/Shanghai npx playwright test -c internal/ui/e2e
```

测试浏览器沿用既有上海时区。CLI 造数使用相同时区，避免日期比较混入宿主时区差异。

修改 Go 代码时还须执行仓库约定的 `go vet ./...` 和 `go test ./... -count=1`。新增文档执行 `python3 scripts/atlas_audit.py`。

## 结构检查

[结构检查器](../../../scripts/check-ui-system.mjs) 检查以下关系：

- 项目语义 Token 只在一份真源声明，引用均能解析。
- 页面字号使用七档语义角色，禁止另写近似像素值。
- 页面不追加 SVG 几何路径或修改图标注册表。
- 图标名称能够对应官方原件，生成物与来源一致。
- 产品与组件目录加载同一共享原语。
- 组件目录不加载业务启动代码。
- 文档四层入口与相对链接可达。
- 文本插值继续转义；脚本遵守产品 CSP。

该离线结构检查也接入 CI。它不需要控制面、浏览器或重新下载图标。

## 交互与状态

[设计系统测试](../e2e/design-system.spec.mjs) 验证组件目录、官方图标资源、密度与字号独立、主题继承，以及窄屏与键盘。[字号测试](../e2e/typography.spec.mjs) 验证主页、用户列表和表单的真实字号，覆盖深浅主题与手机。

[主页测试](../e2e/home-workspace.spec.mjs) 验证真实创建用户、详情、导航、主题与键盘。[主页布局测试](../e2e/overview-fit.spec.mjs) 覆盖深浅主题、最小桌面窗口、1440px 桌面、390px 手机和长名。

其余组件按[组件契约](components.md)所链接的真实流程测试。重点检查正常、空、读取、失败、不可用与保存结果。没有的状态标为不适用，不造假状态凑清单。

## 可访问性

从真实入口使用 Tab、Shift+Tab、Enter、Space 和组件支持的方向键。检查可见焦点、控件名称、状态语义与错误关联。模态组件按[交互模式](patterns.md)核对焦点进入、约束和恢复。

普通文字按真实前景与背景检查对比度。透明表面须计算实际叠加颜色。状态不只靠颜色。纯图标控件保留可访问名称和可见焦点。

当前回归不等于完整 WCAG 合规认证。[交互模式的现有边界](patterns.md#现有边界)须在相关组件迁移时补齐。

## 视觉证据与基线

截图使用真实组件和产品挂载路径。固定视口、主题、字体、数据与设备像素比，等待内容稳定。交付画面使用至少 2x 截图。

用户已认可主页整体方向，并要求移除深色侧栏的深蓝感。中性炭灰修订须单独留图。首次自动截图属于候选基线；只有经用户认可或约定评审接受后，才加入像素回归基线。不要批量更新截图消除未知失败。

主操作、状态切换与首次进入保留适用的录屏或三帧。静态截图无法证明动效。减少运动模式仍须可操作并显示结果。

Windows 平台模拟只能证明相应布局分支。原生字体、窗口与系统行为需要原生证据。

## 结果记录

记录修改范围、状态、主题、视口、检查命令、通过与失败、证据路径和未验证项。证据放任务目录；长期规范留在本目录，执行计划和工作状态留在对应 UC 卡。
