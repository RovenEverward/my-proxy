# 一键更新

把整套 MPX 升到最新版：控制面、每台节点上的代理核心，以及你电脑上的 MPX 桌面程序。点一次按钮，按顺序全部完成。

## 什么时候有更新

MPX 每分钟检查一次新版本。有可升级的部分时，窗口右上角出现 **更新** 按钮。没有这个按钮，说明全部已是最新。

## 前提

- **控制面是 v0.6.1 或更新的版本。** v0.6.0 及更早装的控制面没有远程升级组件，要在 VPS 上运行一次安装脚本补上，之后就能在窗口里更新：

  ```bash
  curl -fsSL https://raw.githubusercontent.com/RovenEverward/my-proxy/main/deploy/install.sh | sudo bash -s -- --addr 0.0.0.0:8080
  ```

  `--addr` 要和控制面现在的监听地址一致，首次安装向导默认是 `0.0.0.0:8080`。机器上已经有 `mpx.service` 时不写 `--addr` 也行，脚本会沿用原来的监听地址；但 v0.9.1 以前的脚本会把它改回只听本机，客户端就拉不到订阅了，所以建议照上面带上。

- **MPX 能改写自己的安装目录。** 用 `.deb` 安装的 MPX 在 `/opt/mpx`，普通用户没有写权限：控制面和节点照常升级，最后升级桌面程序这一步会报「没有写权限」。这时从[最新发布页](https://github.com/RovenEverward/my-proxy/releases/latest)下载新的 `mpx-desktop_` 安装包覆盖安装。
- **以前用浏览器版 `mpx ui` 的话**：v0.8.0 以前的 `mpx ui` 没有这个按钮。先在终端运行 `mpx update apply cli` 和 `mpx update apply control` 升到 v0.8.0 以后，或者直接改用 MPX 桌面程序。

## 更新

1. 点右上角 **更新**。弹窗列出每一部分的当前版本和目标版本：
   - **桌面程序**：你正在用的 MPX。
   - **控制面**：VPS 上的 MPX 服务。
   - 每台节点：节点上的 xray（或 sing-box）核心，标着「可升级」或「已是推荐版本」。
2. 看一眼发布说明，点 **重启以更新**。

<Shot name="update" cap="更新弹窗" />

MPX 依次升级控制面、节点、桌面程序。弹窗按这三组逐条显示进度。最后桌面程序自动重启，窗口自动刷新，不需要重新接入。

暂时不想更新，点 **稍后**。同一个版本在本次打开期间不再提示。

## 更新时用户会不会断线

- 升级控制面期间，用户照常上网，只是暂时不能拉新订阅。
- 升级某台节点的核心时，这台节点上的连接会断开一次，客户端会自动重连。

所以最好挑用的人少的时候更新。

## 验证

更新完成后，右上角的 **更新** 按钮消失。左上角显示新的版本号，**总览** 的「控制面」一格显示控制面的新版本。

## 出了问题

| 症状 | 处理 |
| :--- | :--- |
| 弹窗显示「更新失败」 | 失败那一行写明原因。修好原因后再点一次 **更新**；已经是新版本的部分会跳过 |
| 提示安装目录没有写权限 | 你是用 `.deb` 安装的 MPX。从[最新发布页](https://github.com/RovenEverward/my-proxy/releases/latest)下载新的安装包，覆盖安装 |
| 窗口一直显示「正在重启」超过 1 分钟 | 关掉 MPX 再打开 |
