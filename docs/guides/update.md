# 一键更新

把整套 MPX 升到最新版：控制面、每台节点上的代理核心，以及你电脑上的 MPX 桌面程序。点一次按钮，按顺序全部完成。

## 更新

有新版本时，窗口右上角会出现 **更新** 按钮（MPX 每分钟检查一次；没有这个按钮就说明全部已是最新）。

1. 点右上角 **更新**。弹窗列出桌面程序、控制面和每台节点的当前版本与目标版本，下面是这次的发布说明。
2. 点 **重启以更新**。

<Shot name="update" cap="更新弹窗" size="dialog" />

MPX 依次升级控制面、节点、桌面程序，弹窗里逐条显示进度。最后桌面程序自动重启、窗口自动刷新，不需要重新接入。

暂时不想更新，点 **稍后**。同一个版本在本次打开期间不再提示。

## 更新时用户会不会断线

- 升级控制面期间，用户照常上网，只是暂时不能拉新订阅。
- 升级某台节点的核心时，这台节点上的连接会断开一次，客户端会自动重连。

所以最好挑用的人少的时候更新。

## 验证

更新完成后，右上角的 **更新** 按钮消失。左上角显示新的版本号，**总览** 的「控制面」一格显示控制面的新版本。

## 出了问题

| 症状 | 处理 |
| :--- | :--- |
| 弹窗显示「更新失败」 | 失败那一行写明原因。修好原因后再点一次 **更新**；已经是新版本的部分会跳过 |
| 提示安装目录没有写权限 | 你是用 `.deb` 安装的 MPX（装在 `/opt/mpx`，普通用户不能改写）。控制面和节点已经升好了；从[最新发布页](https://github.com/RovenEverward/my-proxy/releases/latest)下载新的 `MPX-<版本>-Linux-amd64.deb`（ARM 用 `arm64`）覆盖安装即可 |
| 窗口一直显示「正在重启」超过 1 分钟 | 关掉 MPX 再打开 |

## 从老版本升上来

::: details 控制面是 v0.6.0 或更早装的
那时的控制面没有远程升级组件。在 VPS 上运行一次安装脚本补上，之后就能在窗口里更新：

```bash
curl -fsSL https://raw.githubusercontent.com/RovenEverward/my-proxy/main/deploy/install.sh \
  | sudo bash -s -- --addr 0.0.0.0:8080
```

`--addr` 要和控制面现在的监听地址一致，首次安装向导默认是 `0.0.0.0:8080`。v0.9.1 以前的脚本不带 `--addr` 时会把监听地址改回只听本机，客户端就拉不到订阅了，所以建议照上面带上。
:::

::: details 以前用浏览器版 mpx ui
v0.8.0 以前的 `mpx ui` 没有更新按钮。先在终端运行 `mpx update apply cli` 和 `mpx update apply control` 升到 v0.8.0 以后，或者直接改用 MPX 桌面程序。
:::
