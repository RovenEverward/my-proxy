# 用 mpx ui 在浏览器里管理

`mpx ui` 在本机起一个只给自己用的管理界面。界面能做的事和命令行完全一样:每个按钮都对应一条已有的 `mpx` 命令,发给控制面的请求也和那条命令发的一样。控制面本身不对外提供网页。

```bash
mpx ui                         # 起在 127.0.0.1:7480,并用浏览器打开
mpx ui --addr 127.0.0.1:9000   # 换一个端口
mpx ui --no-open               # 只打印链接,不打开浏览器
```

它使用当前 profile 的登录信息(`mpx login` 保存的地址和 token),连接的就是命令行连接的那个控制面。按 Ctrl-C 结束。

## 安全

- **只听本机**:`--addr` 只能是回环地址(`127.0.0.1`、`localhost`、`::1`)。Host 头不对的请求会被拒绝。
- **token 不进浏览器**:页面只和 `mpx ui` 通信,由 `mpx ui` 替页面附上 token 再转发给控制面。
- **一次性链接**:启动时打印的链接带一个一次性密钥,打开后换成仅本会话有效的 HttpOnly cookie。这条链接再打开就无效;需要新链接时,重启 `mpx ui` 即可。
- **只转发白名单里的请求**:能转发哪些请求在 `internal/cli/ui.go` 里写明,写请求还必须是同源发起的。
- **危险操作先确认**:删除用户、删除节点、删除入站、删除用途,都要逐字输入名字才会执行。停用用户、吊销订阅、下发配置、排水、安装、体检,都要先点确认。

## 各页面能做什么

| 页面 | 能做的事 | 对应命令 |
| :--- | :--- | :--- |
| 总览 | 后台循环、节点状态、需要处理的用户、通知设置 | `mpx status`、`mpx settings show` |
| 用户 | 新建、编辑、续期 30 天、停用/启用、重置流量、吊销订阅、删除;查看订阅地址 | `mpx user …` |
| 节点 | 用 SSH 密码添加节点的向导(装公钥、建入站和入口、装核心);现场检查、下发、排水、安装核心、体检、查看在线用户和配置预览、增删改 | `mpx node …`、`mpx inbound add`、`mpx host add` |
| 首次安装 | 还没配置控制面时,`mpx ui` 打开的是首次安装向导,和 `mpx init` 走同一条路径;已配置时用 `mpx ui --setup` 进入 | `mpx init` |
| 入站与入口 | 入站和对外入口的增删改 | `mpx inbound …`、`mpx host …` |
| 分流规则 | 规则表的添加、编辑、拖动排序、停用、删除,「其他全部」的去向;某个用户的专属规则;内置规则组;策略组的新建、修改、删除和实时预览;测试一个网址;从旧模板迁移、切换模式 | `mpx rule …`、`mpx group …` |
| 用途 | 用完整 JSON 新建和修改用途、删除、预览;节点和入口的地区、线路、用途标签(改用分流规则后只保留一个版本,订阅不再受它影响) | `mpx purpose …` |
| 设置 | 通用设置、UA 识别规则、客户端模板、下载备份 | `mpx settings …`、`mpx backup` |

表单底部会实时显示等价的命令,照着就能写脚本。

SSH 密码只从浏览器经本机 `mpx ui` 交给一次 SSH 会话,用来装公钥,不落盘、不进日志;等价命令里只写 `--ssh-password`。

## 刻意不做的事

- **恢复备份**:会整库替换,并且要重启控制面,只能在终端里运行 `mpx restore`。
- **导入导出 CSV**:要读写本机文件,请用 `mpx user export` / `mpx user import`。
- **UA 规则试匹配**:规则是 Go 正则,浏览器里的正则引擎和它不一致,请用 `mpx settings rules test`。

## 设置为什么不会被冲掉

`PUT /api/settings` 会整体替换设置。界面每次保存,都先读回最新的一份,只改你动过的字段,再整份写回。规则、模板和其他字段都会原样带回,与 `mpx settings rules add` 等子命令的做法一致。

## 出错时

界面直接显示控制面返回的原话。例如下发失败时显示 SSH 的报错;控制面没有接上下发通道时显示 501。登录失效(401)时,请重新运行 `mpx login`,再重启 `mpx ui`。
