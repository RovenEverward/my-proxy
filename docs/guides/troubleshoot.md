# 用自检排查

有东西不工作时，先跑一次自检。它只检查，不改任何东西。

## 跑一次自检

在左侧点 **自检**，再点右上角 **开始自检**。

<Shot name="doctor" cap="自检" />

顶部三格分别统计正常、警告和失败的项数。下面的表逐项列出检查结果：数据库、后台任务、每台节点、每种订阅格式和流量采样。每一项的 **说明** 写明看到了什么、下一步该做什么。

处理完后，再点一次 **开始自检** 确认。

## 常见症状

| 症状 | 先看 | 处理 |
| :--- | :--- | :--- |
| 装完了、导入了，客户端还是连不上 | 先跑一次自检，看节点那几行 | 节点都正常时，确认 VPS 服务商的防火墙（安全组）放行了入站端口（默认 443）；再在客户端里更新一次订阅 |
| 窗口左上角的圆点是红色，页面读不到数据 | 控制面是否在运行、这台设备是否被吊销 | 被吊销时重新接入，见[在多台设备上管理](/guides/devices) |
| 自检里某台节点「连不上」 | 那一行的说明 | 在节点详情里点 **现场检查**；核对 VPS 是否开机、SSH 端口是否放行 |
| 订阅里没有线路 | 自检的「节点」各项 | 先[添加节点](/guides/add-nodes)；确认用户的套餐包含这台节点 |
| 新建的入站不生效 | 节点详情里是否显示「配置还没下发」 | 在节点详情里点 **下发配置** |
| 客户端拿到的格式不对 | **设置 → 识别规则** | 见[让某个客户端拿到指定格式](/guides/client-format) |
| 打开订阅链接看到一大串文字，不是订阅页 | 是不是用了下载工具或某些 App 的内置浏览器 | 它们拿到的是给客户端的配置文本；换系统浏览器（Safari、Chrome 等）打开就是订阅页 |
