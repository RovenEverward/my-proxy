# 用体检排查

有东西不工作时，先跑一次体检。它只检查，不改任何东西。

## 跑一次体检

在左侧点 **体检**，再点右上角 **开始体检**。

<Shot name="doctor" cap="体检" />

顶部三格分别统计正常、警告和失败的项数。下面的表逐项列出检查结果：数据库、后台任务、每台节点、每种订阅格式和流量采样。每一项的 **说明** 写明看到了什么、下一步该做什么。配置不一致的警告旁有「应用到<节点>」按钮，点它会跳到这台节点的详情并弹出应用确认。

处理完后，再点一次 **开始体检** 确认。

## 常见症状

| 症状 | 先看 | 处理 |
| :--- | :--- | :--- |
| 装完了、导入了，客户端还是连不上 | 先跑一次体检，看节点那几行 | 节点都正常时，确认 VPS 服务商的防火墙（安全组）放行了入站端口（默认 443）；再在客户端里更新一次订阅 |
| 首次安装时提示 8080（或 443）端口已被占用 | 检查页里写明的占用程序 | 向导会自动换一个空闲端口并告诉你换成了几号，照常继续即可；要自己指定，在向导「设置」那一步的 **高级 → 监听地址** 里改。换了端口的话，接入其他设备时控制面地址要带上新端口，并确认 VPS 防火墙放行它 |
| 添加节点时提示端口已被占用 | 「建入站和入口」那一行的说明 | 点 **改端口** 换一个，或停掉占用它的程序后点 **重试这一步**，见[添加节点](/guides/add-nodes#端口被占用) |
| 窗口左上角的圆点是红色，页面读不到数据 | 控制面是否在运行、这台设备是否被吊销 | 被吊销时重新接入，见[在多台设备上管理](/guides/devices) |
| 体检里某台节点「连不上」 | 那一行的说明 | 在节点详情里点 **刷新状态**；核对 VPS 是否开机、SSH 端口是否放行 |
| 订阅里没有线路 | 体检的「节点」各项 | 先[添加节点](/guides/add-nodes)；确认用户的套餐包含这台节点 |
| 新建的入站不生效 | 节点详情的 **节点配置** 是否显示「有改动未应用」或「还没应用过」 | 在节点详情里点 **应用到节点** |
| 客户端拿到的格式不对 | **订阅 → 客户端识别** | 见[让某个客户端拿到指定格式](/guides/client-format) |
| 打开订阅链接看到一大串文字，不是订阅页 | 是不是用了下载工具或某些 App 的内置浏览器 | 它们拿到的是给客户端的配置文本；换系统浏览器（Safari、Chrome 等）打开就是订阅页 |
