# 一个入口，多张面孔

> 待确认：Agent 从 [设计](../../design.md) 里「推翻过的一条：不做 Web UI」、[管理 UI 方案](../../internal/ui-rfc.md) 和 [桌面程序方案](../../internal/desktop-rfc.md) 提炼，请主人确认说法。

> **30 秒版**：MPX 的能力只有一套，就是控制面的管理接口。命令行、本机网页 `mpx ui`、桌面程序是同一套能力的三张面孔：界面可以先行、可以更好用，但不能长出接口之外的能力，也不能把管理入口暴露到公网。

## 这个想法是什么

**入口只有一个。** CLI 是 `/api` 的纯客户端，每条命令都能用 `curl` 等价做出来。最初的设计因此「不做 Web UI」。用户到了几百上千，「谁快到期、谁超限、哪台节点在退避」要连敲几条命令再在脑子里拼，CLI 一屏看不全，于是推翻了这一条，但保留它真正要守的两件事：入口只有一个、UI 不长出 CLI 没有的能力。

**UI 跑在操作机上，不跑在控制面上。** `mpx ui` 只听回环地址，页面请求带上 CLI 那份 token 原样转给 `/api`，控制面一行不改。如果管理页由 `mpx serve` 提供，它就会和订阅一起暴露到公网，控制面得为它加会话、CSRF、登录限流，token 也要进浏览器。

**UI 优先，但不扩权。** 现在的方向是每个功能都要能在 `mpx ui` 里做，桌面程序用 MyGo 把同一个 `mpx ui` 装进窗口，不另起前端。需要在客户端机器上动手的事（切换配置档、自检、relabel、首次安装）走本机接口，而不是让控制面替它做。

**接口只增不破。** 三张面孔会以不同的速度升级，旧 CLI、旧 `mpx ui` 必须照常连新控制面。要破坏兼容，先停下来问。
