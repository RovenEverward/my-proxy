# 不登录 VPS

> 待确认：Agent 从 [设计](../../design.md) 的「核心原则」、[设备接入方案](../../internal/device-connect-rfc.md)、[自动升级方案](../../internal/update-rfc.md) 和 [桌面程序方案](../../internal/desktop-rfc.md) 的设计原则提炼，请主人确认说法。

> **30 秒版**：用户永远不用登录 VPS 操作。把一台 VPS 变成控制面或节点、让新设备接入、升级控制面，都在用户自己的设备上完成。

## 这个想法是什么

**装是一行命令。** `mpx init` 在用户电脑上经 SSH 把控制面和第一个节点装好，打印订阅地址；不想敲命令就用 `mpx ui` 的首次安装向导，步骤一样。SSH 密码只在这一刻用一次，之后改用密钥，也不落盘。

**装好之后不再 SSH。** 每台设备通过控制面的 HTTPS 管理接口接入。用户不用配证书、反向代理或域名：控制面自签证书，CLI 按指纹认它；管理接口和订阅共用一个端口，省一次安全组放行；新设备的凭据是用户在安装时设的设备密码，不用去机器上翻 token。多台设备是常态，每台各自接入、各自可吊销。

**升级也在自己设备上。** 起初的决定是「只提醒，升级由人重跑安装脚本」，因为替换的正是控制面自己。后来按 [自动升级方案](../../internal/update-rfc.md) 加了远程升级：校验哈希、试跑、原子替换、保留上一版、健康检查不过自动换回，用户在本机一条 `mpx update apply` 就能完成，也能 `rollback`。

## 它带来什么、代价是什么

`mpx init` 成了 CLI 里唯一会 SSH 的地方，是「CLI 不碰节点」的例外，理由是那一刻控制面还不存在。订阅仍走明文 HTTP，因为代理客户端普遍不认自签证书。
