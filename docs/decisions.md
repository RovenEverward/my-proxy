# 关键决策与理由

理由是承重的。只留结论,后来的人会把它当风格问题随手改掉。

## 1. 参考 Marzneshin 的模型,但不复用它的代码

目标里明确要求不复用,而且 Marzneshin 的状态机比这里需要的复杂(services 分组、host chains、node usage ratio、多管理员)。

**借的是模型而非实现**:五张表、User-Agent 规则、订阅响应头这几处形状来自它;代码是全新的 Go。

## 2. 用系统自带的 `ssh` 可执行文件,不引 `golang.org/x/crypto/ssh`

一台机器怎么连(跳板机、`ssh-agent`、`~/.ssh/config`、`known_hosts`)在操作者机器上已经是既成事实。重写一份 SSH 客户端只多出一处会漂移的真相,还得把那些能力再补一遍。

## 3. 结构变更走 `node sync`,人员名单走周期收敛

- **结构变更**(加入站、改端口、换证书)必须重启 xray 才生效 → 人显式触发 `mpx node sync <id>`,全量下发 + 重启。
- **人员名单**(加人、摘人、到期、超限)走每轮增量收敛,只调 `xray api adu/rmu`,**不重启**。

理由:配额恢复和到期续费都会触发加用户。如果每次都重启,节点上所有人的连接都会跟着断一次。

## 4. 控制面启动时不下发配置

启动意味着重启 xray。控制面重启是常事(升级、改配置、机器重启),不该因此把每个节点上所有人的连接断一次。启动后自动做的只有人员名单收敛。

## 5. 只有控制面能 SSH,CLI 不能

能 SSH 到节点的是控制面那台机器,不是操作者手边这台笔记本。所以下发通道接在控制面进程里,CLI 只发 HTTP。

## 6. 单 token 鉴权

`/api/*` 走一个固定 Bearer token。没有管理员表、没有会话、没有权限分级。

**配套约束**:token 为空时完全不校验鉴权,因此这种模式只允许绑回环地址;绑非回环 + 空 token 会在启动时直接拒绝。

`/sub/*` 不鉴权 —— 订阅 token 即凭证。

## 7. 密钥派生用 SHA-256 域分隔 + X25519

不用 Marzneshin 的 `xxhash` / `nacl`,改用 Go 标准库:

- `derive(domain, key) = sha256(domain + ":" + key)`;UUID 取前 16 字节并补 RFC4122 版本位与变体位,密码取前 16 字节 hex。
- REALITY 密钥对用 `crypto/ecdh` 的 X25519。

理由:两边的 Key 体系本来就不通用,而标准库足够、零依赖。

## 8. 地址里的变量用用户名派生,不用随机数

`{SERVER_IP}`、`{USERNAME}` 这类变量要展开,`*` 要换成子域。这里的随机**必须由用户名派生**(`sha256("salt:" + username)` 取前 6 字节)。

用真随机数的话,客户端每次更新订阅都会看到新地址,配置里会堆满废弃节点。

## 9. 流量用 `statsquery -reset` 读走即清零

节点按 `email`(= 用户名)聚合流量分桶。控制面每轮读一次并**顺手清零**,读回的就是「这一轮的增量」,直接累加进 `used_traffic` 和 `lifetime_used_traffic`。

理由:控制面不需要记住上次读到多少,也就没有「上次读数」这个会失步的状态。

## 10. SQLite 单连接 + WAL

纯 Go 驱动 `modernc.org/sqlite`(不引 cgo),连接池上限 **1 条**,`journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`、`synchronous=NORMAL`。

理由:控制面是单进程,连接池 1 条就消除了写冲突;WAL 让订阅读取不被流量写入挡住。

**代价**:遍历 `*sql.Rows` 期间不能再发起查询,否则会等自己持有的那条连接而死锁。这条约束写在 `internal/store/store.go` 的包注释里。

## 11. 级联删除靠外键,不靠应用层

`ON DELETE CASCADE` 让 `DeleteNode` / `DeleteInbound` 各只需一条 `DELETE`。应用层逐表删是第二份真相,早晚会漏一张。

## 12. 订阅渲染与节点配置渲染不共用代码

两边的目标不同:客户端配置要的是「怎么连」,节点配置要的是「怎么被连」。硬合成一份会到处是 `if 是节点侧`。

但它们共用中间表示 `Endpoint` 之前的输入(同一个 `Resolve` 展开入口),所以「哪些 host 属于这个用户」这件事只有一份实现。
