# 故障排查手册 (Troubleshooting)

本文按照故障现象与诊断工具提供针对性的排查步骤与解决方案。

---

## 1. 核心体检工具：`mpx doctor`

在面对任何系统异常时，首先运行内置体检命令：

```bash
mpx doctor
```

命令会逐项检查系统内部状态，每个检查项输出 `[ok]` 或 `[fail]`。退出码规则：
- `0`：全部检查项通过。
- `3`：存在至少一项严重错误。

### 检查项与修复指南

| 检查项 | 失败原因分析 | 解决办法 |
| :--- | :--- | :--- |
| **`db_accessible`** | 数据库文件不存在、权限不足或磁盘已满 | 检查 `/var/lib/mpx/data.db` 文件属主（必须为 `mpx:mpx`）及磁盘剩余空间 (`df -h`)。 |
| **`ssh_key_present`** | 本地 SSH 私钥文件丢失或路径不可读 | 检查 `/var/lib/mpx/.ssh/id_ed25519` 是否存在，执行 `chmod 600`。 |
| **`node_reachable`** | 远端节点网络不通、端口屏蔽或公钥未授权 | 登录控制面尝试 `ssh -i <私钥> <user>@<node_ip> -p <port>` 手动验证；检查节点防火墙。 |
| **`xray_running`** | 节点上的 xray systemd 服务异常退出或崩溃 | SSH 登录节点，执行 `systemctl status xray` 及 `journalctl -u xray -n 50` 查看 xray 原生报错日志。 |
| **`config_consistent`** | 节点本地 `/etc/xray/config.json` 与数据库期望配置不一致（配置漂移） | 执行 `mpx node sync <id>` 强制向节点重新推流并重载进程。 |
| **`cert_validity`** | 使用了自有 TLS 证书且证书即将过期（7天内） | 更新节点上的证书文件并执行 `mpx node sync <id>`。如为免证书建议切换为 REALITY 协议。 |

## 2. 常见问题与典型场景

### 场景一：用户反映客户端无法拉取订阅

1. **检查订阅前缀**：
   运行 `mpx settings get`，确认 `sub_url_prefix` 是否正确设置了外网能访问的域名或公网 IP。如果为 `http://127.0.0.1:8080`，外部网络无法访问。
2. **检查用户状态**：
   ```bash
   mpx user get <username>
   ```
   检查用户的 `status` 是否为 `active`，已用流量是否超标，是否已过过期时间。
3. **检查 Token 是否正确**：
   如果用户曾在 Web 端点击「换个订阅地址」，原链接当场失效，请在 `mpx user links <username>` 重新获取最新链接。

---

### 场景二：用户能拉取订阅，但所有节点无法联网

1. **观察拉取到的节点名称**：
   如果客户端里的节点名字变成了：
   - `【账号已停用】请联系管理员`
   - `【账号已过期】请续费后使用`
   - `【流量已超限】当前周期已用尽`
   
   说明服务端因策略限制，显式下发了占位死节点（`0.0.0.0:1`）。为用户充值或续期：
   ```bash
   mpx user renew <username> --days 30
   mpx user reset-traffic <username>
   ```

2. **客户端本地时间偏差**：
   对于 VLESS / VMess 协议，若客户端设备（手机、电脑）本地时间与标准时间相差超过 90 秒，TLS / 时间戳握手会直接被底层拒绝。校准客户端本地系统时钟。

---

### 场景三：节点处于「退避中」状态，拒绝同步

1. **查看退避状态**：
   运行 `mpx status`，查看「退避节点」列表中列出的节点 ID 及下一次重试倒计时。
2. **强制重测并退出退避**：
   在修复了远端主机的网络或 SSH 权限后，立即触发单节点测试：
   ```bash
   mpx node test <id>
   ```
   测试通过后，系统自动清空该节点的失败计数与退避延迟，恢复正常心跳。
