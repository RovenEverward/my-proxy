# 节点运维与生命周期管理

本文介绍节点添加、软件安装、配置同步、平滑排空（Drain）维护以及在线用户查询的操作步骤。

---

## 1. 添加与安装节点

### 注册节点元数据

向数据库录入节点基础连接信息：

```bash
mpx node add hk-01 --address 203.0.113.10 --ssh-port 22 --ssh-user root
```

可选参数：
- `--ssh-password`：交互式提示输入一次远程机器的 SSH 密码。控制面会使用该密码自动把自身的公钥推送到节点的 `authorized_keys` 中，完成后密码立即销毁不留痕迹（之后全部走密钥免密通信）。
- `--api-port 10085`：指定 xray 节点内 gRPC 统计接口的监听端口（默认 10085）。
- `--config-path /etc/mpx/xray/config.json`：自定义配置文件路径。
- `--service-name mpx-xray`：自定义 systemd 服务名。

### 一键安装与初始化 xray

在远程节点上全自动完成环境初始化：

```bash
mpx node install 1
```

执行流程说明：
1. 建立 SSH 连接，检测目标架构（amd64 / arm64）。
2. 从 GitHub Release 下载适配版本的 xray 核心及 geoip/geosite 数据。
3. 部署 systemd 守护单元 `/etc/systemd/system/xray.service`。
4. 启动进程并设置开机自启。

升级已有节点的核心版本：
```bash
mpx node install 1 --version v26.3.27
```

## 2. 结构变更与配置同步（Sync）

当对入站做出了**结构性改动**（例如：增删入站、更改监听端口、切换传输协议、更换 TLS 证书路径）后，必须向节点下发新配置文件并重启进程：

```bash
# 同步单台节点
mpx node sync 1

# 同步全部节点
mpx node sync
```

> **提示：增删用户不需要 sync**。
> 控制面后台循环会自动通过 gRPC 动态下发和注销用户凭证，不会中断节点的现有网络连接。只有涉及端口、协议、传输层等底层配置修改时，才需要执行 `node sync`。

## 3. 节点平滑维护（Drain 优雅排空）

当需要对服务器进行关机、迁移或重启维护时，直接中断服务会导致已连接用户的长连接瞬间断开。mpx 提供了分阶段排水能力。

### 开启排空模式

```bash
mpx node drain 1
```

**生效机制**：
1. 节点进入 `draining` 状态，所有新生成的客户端订阅中将不再包含该节点（阻止新用户涌入）。
2. 远端 xray 保持原样运行，现有的活动连接（如视频流、下载）不受影响，继续通信。

### 查看剩余连接并等待排空

```bash
mpx node drain 1 --status
```
输出当前剩余的活动连接数。等待连接数归零或下降至安全阈值。

### 维护完毕恢复节点

服务器维护完成后，重新恢复接受新流量：

```bash
mpx node drain 1 --off
```
节点状态恢复为 `active`，下一次订阅更新时重新展示该节点。

## 4. 实时在线连接与活跃 IP 查询

查看当前哪些用户正在哪个节点上产生流量：

```bash
# 查看所有节点的在线活跃连接
mpx node online

# 查看指定节点过去 5 分钟内的活跃 IP
mpx node online 1 --window 5m
```

输出样例：
```
节点: hk-01 (ID: 1)
用户       协议     远程 IP           最后活跃时间
alice      vless   198.51.100.24     10 秒前
bob        vmess   203.0.113.88      1 分钟前
```

## 5. 故障退避机制说明

当节点因机房断网或 SSH 密钥变更导致探活失败时，控制面会触发**退避重试**机制：
- 失败后重试间隔以指数退避增加（10s、30s、1m、5m……最大 15m）。
- 退避中的节点在 `mpx status` 中会明确展示为退避状态。
- 网络修复后，可使用 `mpx node test <id>` 强制进行一次重测，成功后立即消除退避状态。
