# RFC：mpx ui 的两个向导——密码添加节点、首次安装

> 状态：已批准（2026-10-16，SSH 密码可以经过浏览器，其余待定项采纳推荐）· 起草基于 main 793a205
> 这份 RFC 推翻了 `ui-rfc.md` §1「`mpx init` 这类 SSH 编排留在 CLI」和节点页「密码不经过浏览器」的说法，两处已同步改。
> 依据的现状（已对照代码）：`internal/cli/init.go`、`internal/cli/bootstrap.go`、`internal/cli/node.go`（node add）、`internal/server/api.go`（handleCreateNode）、`internal/node/askpass.go`、`internal/cli/ui.go`（uiAllow）、`internal/ui/ui.go`、`internal/ui/assets/nodes.js`、`docs/internal/ui-rfc.md`

## 目标与能力清单

用户不登 VPS、也不必敲命令，就能在 `mpx ui` 里完成两件目前只能在终端做的事。

| 能力 | 状态 |
| --- | --- |
| 向导 A：输入 SSH 密码添加一台新 VPS，跑完它就进了订阅（节点 → 入站 → 入口 → 装核心并下发） | 设计内 |
| 向导 B：首次安装，等价于 `mpx init`（装控制面、建第一个节点和用户、设设备密码、本机自动接入） | 设计内 |
| 每一步都显示等价 CLI 命令（沿用现有「页面能做的 = CLI 能做的」的约定） | 设计内 |
| 用密钥代替密码登录 | 设计内（A 由控制面密钥负责，用户不需要；B 留一个「已能用密钥登录」的选项） |
| 记住 SSH 密码、「下次自动填」 | 不做：密码只是一次性钥匙，见决策 2 |
| 分离部署（控制面和第一个节点不在同一台） | 不做：`mpx init` 本身也只做单机全包，分离部署走向导 A |
| 向导 B 失败后自动卸载控制面 | 不做：卸载是破坏性的，而且 init 每步都可以安全重跑，见失败模式 |
| 在网页里改 sshd 配置、开防火墙端口 | 不做：超出「装好就能用」的范围 |

### 现状与这次要推翻的一条决定
- `POST /api/nodes` **已经接受** `ssh_password`：控制面先用 askpass 登一次，把自己的公钥追加进节点的 authorized_keys，装不上就不建节点（api.go `handleCreateNode`）。CLI `node add --ssh-password` 用的就是这条。
- 当前 UI 刻意不收密码：添加节点抽屉写着「密码不经过浏览器，请在终端用 `--ssh-password`」（nodes.js:129）。ui-rfc.md:28 也把 `mpx init` / `bootstrap` 这类 SSH 编排列为留在 CLI。**本 RFC 推翻这两处**，理由见决策 1。拍板后要同步改这两处文字。
- `mpx ui` 现在必须先配好控制面才能启动（ui.go：`没配置控制面地址:先跑 mpx connect`）。首次安装时控制面还不存在，所以向导 B 不能走转发。

## 关键决策与理由

1. **密码可以经过浏览器，但只走「浏览器 → 本机 mpx ui → 一次 SSH」这一段，用完即丢。**
   浏览器和 mpx ui 之间是回环地址，有一次性 key 换来的会话 cookie 和严格 CSP；mpx ui 到控制面是按指纹锁定的 HTTPS。这和用户在终端里输密码相比，多出来的暴露面只有浏览器进程的内存。换来的是不会命令行的用户也能加节点。
   不选「让用户去终端」：这正是向导要消除的门槛。

2. **密码绝不落盘，也不进日志和进程参数。** 这是沿用现有做法，不是新机制：
   - 控制面和 CLI 都通过 `SSH_ASKPASS` 加环境变量 `MPX_ASKPASS_PASSWORD` 把密码交给 ssh。临时目录里的 askpass 脚本只有 `printf '%s' "$MPX_ASKPASS_PASSWORD"` 一行，不含密码，用完 `RemoveAll`。
   - 请求体里的 `ssh_password` 不进 `model.Node`，也不进库。
   - 新增要求：
     - 前端提交后立刻清空密码输入框，不放进 localStorage、URL 或等价命令文本（等价命令里写成 `--ssh-password`，提示会在终端询问）；
     - mpx ui 的转发层和本地接口不记录请求体；
     - 向导 B 的任务对象在公钥装好之后立刻丢掉对密码的引用。
   - 理由：密码要么是机房给的初始密码，要么和别的机器共用，落盘一份就多一份泄露面；公钥装好之后它已经没用了。
   - 已知局限：Go 字符串没法可靠清零，进程内存里会残留到被 GC 回收为止。这一点写进安全说明，不再加更多机制。

3. **向导 A 全部用控制面现有接口拼起来，不新增控制面接口。** 顺序照 `mpx bootstrap`：
   1. `POST /api/nodes`（带 `ssh_password`）；
   2. `POST /api/inbounds`（默认 VLESS + TCP + REALITY，443，SNI 和回落目标 `www.cloudflare.com`，与 bootstrap 默认值一致）；
   3. `POST /api/inbounds/{id}/hosts`；
   4. `POST /api/nodes/{id}/install`（安装核心，同时下发配置）。

   每一步都对应一条已有 CLI 命令，e2e 可以继续用「同一件事 CLI 发了什么、页面发了什么」逐条对照。uiAllow 里已经放行了 `POST /api/nodes` 和 `POST /api/inbounds`，不用改。

4. **向导 B 跑在本机 mpx ui 进程里，是「控制面之前」的唯一例外。** 新增的接口都挂在 mpx ui 自己的本地服务上（前缀 `/local/setup/`），不进控制面 API，也不经过 uiAllow 转发。
   - 理由和 `mpx init` 一样：控制面还不存在，只能从本机 SSH。
   - 实现上把 `runInit` 拆成「参数 → 带进度回调的步骤序列」，CLI 和向导共用一份，不复制粘贴。
   - 入口：`mpx ui` 发现没配置控制面时，不再报错退出，而是进入「首次安装」模式（另加 `--setup` 用于已有控制面时显式进入）。见待定项 1。

5. **长任务用「建任务 + 轮询」，不用 WebSocket 或 SSE。** 安装控制面最长 25 分钟（init 的超时预算），浏览器可能刷新。
   - 本地服务只保留一个进行中的任务，状态放在内存里；页面每 2 秒查一次，刷新后能接着看。
   - 现有前端全是 fetch 加轮询，不为这一处引入新的传输方式。

## 向导 A：用 SSH 密码添加节点（4 步）

入口：节点页「添加节点」按钮旁边，或空态卡片上的「用密码添加一台 VPS」。原来的抽屉保留给「已能免密 SSH」的情况。

| 步 | 字段与默认值 | 前端校验（文案） | 失败时（服务端原话 + 我们的提示） |
| --- | --- | --- | --- |
| 1 连接 | 地址（必填）；SSH 端口 22；SSH 用户 root；SSH 密码（必填，眼睛按钮可显示）；节点名（必填，同 `node add` 的位置参数，例如 jp-2；显示名之后由自动识别生成） | 「请填写服务器地址」「端口要在 1–65535 之间」「请输入 SSH 密码」「请填写节点名」「节点名不能是纯数字」（服务端 `numericNodeName` 也会拦） | 下一步才会真正发请求，这一步不连机器 |
| 2 入站 | 预设「REALITY · 443（推荐）」；高级里可改端口、SNI、回落目标 | 「端口要在 1–65535 之间」「回落目标写成 域名:端口」 | — |
| 3 安装 | 只读进度清单：登录并装公钥 → 登记节点 → 建入站和入口 → 装核心并下发 | — | 见下表 |
| 4 完成 | 显示自动识别出的显示名（如 🇯🇵 东京 B，用 `locate_note` 提示识别失败）、它进了哪些订阅、默认套餐会自动包含它；按钮「查看节点」「再加一台」 | — | — |

第 3 步各环节失败时：
- **装公钥失败**（`POST /api/nodes` 返回 502）：原样显示 ssh 的原话（密码错、没开密码登录、连不上），按钮「返回修改」回到第 1 步，密码框清空要求重输。这时节点没有建，不需要回退。
- **建入站或入口失败**：节点已经建了。给两个选择：「重试这一步」，或「删除刚加的节点」（`DELETE /api/nodes/{id}`，二次确认）。公钥已经在节点上，重试不再需要密码。
- **装核心失败**：节点、入站、入口都保留，显示失败原因，提供「重试安装」（`POST /install`）和「稍后在节点页处理」。不自动删除，因为常见原因是机器暂时下不了包，过后重试即可。
- **页面关掉或刷新**：向导 A 的每一步都是一次普通的同步请求，状态就在控制面里；回到节点页能看到半成品，点进去可以接着装核心。

## 向导 B：首次安装（5 步，对应 `mpx init`）

| 步 | 字段与默认值 | 校验（文案） |
| --- | --- | --- |
| 1 连接 VPS | 地址（必填）；SSH 端口 22；登录方式：密码（默认）或「这台电脑已能用密钥登录」（可选填私钥路径）；SSH 用户固定 root（init 要求 uid=0），放在高级里 | 同向导 A |
| 2 检查机器 | 自动执行：用密码登一次并把本机公钥装上去 → probe（`uname`/`id -u`/curl 或 wget） | 不通过时直接用 init 的原文案：「控制面要在 Linux 上跑，这台机器报的是 X」「要用 root 登录」「这台机器上既没有 curl 也没有 wget…」 |
| 3 设置 | 第一个用户名 user1；节点名 default（建议改成地区名）；设备密码 ×2（≥12 字符，与 `minDevicePasswordLen` 一致）；高级：监听地址 0.0.0.0:8080、订阅前缀、SNI | 「设备密码至少 12 个字符」「两次输入不一致」「用户名只能用字母、数字、- 和 _」（用户名规则以 `validateUser` 为准） |
| 4 安装 | 进度清单照 init 的 step 文案：送安装脚本 → 装控制面 → 建节点、入站、入口、订阅设置与用户 → 设置设备密码 → 本机接入。每步显示耗时，可展开最近 50 行输出 | — |
| 5 完成 | 订阅链接加二维码（用户 user1）、给别的设备用的 `mpx connect <host:port> --fp …`、证书指纹；按钮「进入管理界面」把 mpx ui 切成正常模式，连接刚存下的配置档 | — |

本地新增接口（只挂在 mpx ui 的本地服务上，同样要会话 cookie）：

| 接口 | 作用 |
| --- | --- |
| `GET /local/setup` | 返回当前模式（setup / normal），以及是否有进行中的任务 |
| `POST /local/setup/check` | 对应第 2 步，同步返回 probe 结果；密码装好公钥后就不再保留 |
| `POST /local/setup/run` | 对应第 4 步，建任务（已有进行中的任务返回 409），立即返回 202 |
| `GET /local/setup/run` | 返回任务状态：当前步、每步状态和耗时、输出尾部 50 行、结束结果（订阅链接、指纹、connect 命令） |
| `POST /local/setup/finish` | 把 mpx ui 切换成连接新控制面的正常模式 |

失败与回退：
- init 的每一步都可以安全重跑（已有的节点、入站、入口、用户会复用）。所以任何一步失败都显示「重新运行」，从第 4 步开头再跑一遍，不做逐步回滚，也不自动卸载控制面。
- 失败页同时给出等价命令 `mpx init --host … --ssh-password`，作为终端兜底。
- 本机接入失败（控制面已经装好）时，完成页给出 `mpx connect <host:port> --fp <指纹>`，不算整体失败。
- mpx ui 进程退出（关终端）后任务就中断了：远端装到一半的状态由下次「重新运行」接上。页面在第 4 步提示「安装期间不要关闭运行 mpx ui 的终端」。
- 副作用说明（完成页和 CLI 一致）：本机会生成或复用 `~/.ssh` 里的一把密钥；VPS 上会追加这把公钥，以及控制面自己的公钥。

## 失败模式（两个向导共用）

| 情况 | 表现 |
| --- | --- |
| 密码错，或 sshd 关了密码登录 | 显示 ssh 原话，回到第 1 步，清空密码 |
| 主机密钥第一次见 | 和 CLI 一样 `StrictHostKeyChecking=accept-new`，不提示（TOFU）。是否要先显示主机指纹让用户确认，见待定项 3 |
| 主机密钥变了（重装过系统） | ssh 拒绝连接；显示原话，并提示到 known_hosts 删掉旧行（向导 A 是控制面的 known_hosts，向导 B 是本机的） |
| 慢链路超时 | 沿用现有预算：装公钥 60s，init 各步 60s 到 25min。超时显示是哪一步，给「重试」 |
| 同时点两次 | A：按钮在请求期间禁用；B：本地服务 409 |
| 会话过期，或 mpx ui 重启 | 一次性 key 失效，需要重新打开链接；向导 B 的任务一起丢失，重新运行即可 |

## 待定项与穿刺项

## 补充约束：连接性能（用户 2026-10-16）
- 向导轮询只取增量：`GET /local/setup/jobs/{id}?since=<seq>` 只返回新日志行和当前阶段，单次响应目标 < 4 KB；无变化时返回空增量。
- 轮询间隔从 2 秒起，任务长时间无变化退避到 5–10 秒；页面不可见时暂停轮询。
- 安装日志在服务端截断保留尾部（例如最近 500 行），前端不拉全量日志。
- 不在向导里上传或下载大文件；节点安装包由 VPS 自己从 GitHub Release 拉取，不经过本机转发。
- 测试加一条：一次完整安装过程中，浏览器与 mpx ui 之间的总流量有上限断言。
