# RFC：套餐（权限组）

> 状态：已批准（2026-10-16，§8 全部按推荐项定案，并新增「默认套餐」）· 按 P1–P3 实现（P4 可选）· 起草时基于 main `bc3231c` · 节点一律用显示名

## 已定案（2026-10-16）

1. 一人一套餐；需要加购时用「额外授权」（用户自己的 `inbound_ids`）。
2. 套餐和额外授权取并集。
3. 授权以节点为主，入站可选，不做按入口授权。
4. v1 不做配额和时长；P4 可选，做成「套餐默认值，一次性复制给用户」。
5. **系统自带「默认套餐」**：`all_nodes=true`，以后新加的节点也自动包含；可以编辑，不能删除。升级时自动创建，现有用户和新用户默认都归到它。`mpx plan suggest` 保留，作为可选的整理工具。
6. 空套餐表示什么都不能用；「全部」用 `all_nodes` 显式表达。

### 迁移：每个用户升级前后能用的入站完全一致

| 升级前 | 升级后 | 能用的入站 |
| --- | --- | --- |
| `inbound_ids` 为空（全部入站） | 归入默认套餐（`all_nodes`） | 全部 → 全部 |
| `inbound_ids` 非空（单独勾了入站） | **不归入默认套餐**，否则和全部节点取并集会放大权限。按相同的入站集合分组，每组自动建一个「迁移套餐」，`plan_inbounds` 等于这个集合，名字列出所含节点的显示名，例如「迁移 · 🇺🇸 洛杉矶 A + 🇯🇵 东京 A」 | 原集合 ∪ 原集合 = 原集合 |
| `inbound_ids` 里只剩已删除入站的 id | 迁移套餐为空 | 无 → 无（升级前非空的过期列表本来就匹配不到任何入站） |

- 迁移**不清空**用户的 `inbound_ids`。这样降级回旧版本时（旧版本不认套餐），权限仍然和升级前一样；如果清空了，旧版本会把这些用户当成「全部入站」。
- 代价：迁移来的用户，这份 `inbound_ids` 就成了额外授权，从迁移套餐里去掉节点并不能收窄他们的权限。`mpx plan show` 和接口会标出「N 个用户有额外授权」；要收窄，先 `mpx user edit <u> --inbounds ""` 清空额外授权，套餐的设置才会完全生效。
- 测试按每个用户、每个入站逐一比较迁移前后的 `AllowsInbound`，覆盖：为空、单个、多个、集合相同的多个用户（合并成一个套餐）、全是过期 id。

### 新用户与旧客户端

- 新建用户时：没带 `plan_id` 且 `inbound_ids` 为空，归入默认套餐；带了 `plan_id`，按指定的套餐；**没带 `plan_id` 但带了 `inbound_ids`**（旧客户端或脚本），不挂套餐，按旧语义只能用这些入站，避免和默认套餐取并集后变成全部。
- 用户可以不挂套餐（`plan_id` 为空），这时完全沿用旧语义。只有上面这种旧写法（以及下一条的旧客户端例外）会产生这种状态，而这两种情况都带着非空的 `inbound_ids`，只会收窄权限。
- **不能把用户移出套餐**（2026-10-16 定案）：没挂套餐、`inbound_ids` 又为空的用户按旧语义能用全部入站，所以「移出套餐」会让权限悄悄回落到全部节点。因此：
  - `PUT/POST /api/users` 带 `plan_id: null` 返回 400；`mpx user edit --plan ""` 在本地就拒绝。要「放宽到全部」，请明确改挂到默认套餐。
  - 删除套餐时，如果套餐里还有用户，`reassign` 没填或为空都返回 409，提示用 `reassign` 指定一个具体套餐（可以是默认套餐）；`mpx plan rm --reassign ""` 在本地就拒绝。套餐里没有用户时照常删除。
- 旧客户端整体 `PUT` 用户、不带 `plan_id` 时，保持原来的套餐。例外：`all_nodes` 套餐下的用户被写入了非空的 `inbound_ids`，在 `all_nodes` 下这只可能是调用方想限制这个用户（取并集没有意义），这时摘掉套餐，按旧语义生效。这条规则放在 store 的用户更新里，API、CLI、CSV 导入走同一条路径。

## 1. 问题陈述

管理员要先定义几档套餐，比如「基础」只有 🇺🇸 洛杉矶 A，「全球」包含 🇺🇸 洛杉矶 A/B、🇯🇵 东京 A、🇸🇬 新加坡 A，再把用户挂到套餐上。现在只能给每个用户单独写入站 id，存在三个问题：

- 加了新节点，要逐个用户去改；
- 管理员看不出谁属于哪一档；
- 页面上授权显示成 `#3 #5` 这样的入站 id，看不出对应哪台机器。

| 分流的策略组只从**该用户自己的端点**里挑成员（`endpointsFor` 已经按授权过滤）。组里没有成员时只放 DIRECT，并给出警告 | `server/routing.go`、`render/routing.go` |

**结论：**只要让 `AllowsInbound` 认识套餐，并把满员计数那一处改成也调用它，订阅、xray 下发和收敛就会自动跟着生效，不需要逐条改调用点。

## 3. 拟定方案

### 3.1 数据模型

```text
plans(id, name UNIQUE, note, all_nodes BOOL)
plan_nodes(plan_id → plans ON DELETE CASCADE, node_id → nodes ON DELETE CASCADE)
plan_inbounds(plan_id → plans ON DELETE CASCADE, inbound_id → inbounds ON DELETE CASCADE)
plans.is_default BOOL                     -- 恰好一个，不能删除
user_plans(user_id PK → users ON DELETE CASCADE, plan_id → plans)   -- 不在 users 表加列：用户的整体 PUT 路径保持不动
```

拟定的接口形状（尚未实现，不是真实返回）：

```json
{"id": 2, "name": "全球", "note": "", "all_nodes": false,
 "node_ids": [1, 2, 3, 4], "inbound_ids": [],
 "users": 5}
```

- **按节点授权为主，按入站授权为辅。**勾选一个节点，就包含它的全部入站，**包括以后在这台节点上新加的入站**，这正好解决「加节点要逐个改」的问题。只想开放某个协议时，再单独勾选入站。
- **不做按入口（host）授权。**同一个入站的所有入口共用同一份 xray clients，服务端拦不住，只能在订阅里藏起来，算不上真正的权限。列入 Non-goal。
- **空套餐表示什么都不能用**，和 `inbound_ids` 为空表示全部正好相反。这是有意的：「全部」用 `all_nodes: true` 显式表达，以免把空套餐误当成全开。

### 3.2 一人一套餐还是多套餐：推荐一人一套餐

| | 一人一套餐（推荐） | 一人可挂多个套餐 |
| --- | --- | --- |
| 心智 | 「alice 是全球套餐」，和商业套餐的说法一致 | 「alice 有基础 + 日本加购」 |
| 存储 | `user_plans` 一张表，每个用户一行 | 再加一张 `user_plans` 关联表 |
| 判定 | 取一个集合 | 取并集；要是以后套餐里带配额，就得定义多个配额怎么叠加 |
| 代价 | 需要加购时，要多建一个组合套餐 | 复杂度落在配额、展示和 CSV 上 |

真有加购需求，单个用户仍然可以在套餐之外追加入站（见 3.3），不必为了少数情况引入多套餐。

### 3.3 和现有单独授权怎么共存

生效规则写在 `AllowsInbound` 一处：

1. `plan_id` 为空：完全沿用旧行为，`inbound_ids` 为空表示全部。**升级后什么都不变。**
2. `plan_id` 不为空：可用范围 = 套餐的入站 ∪ 用户自己的 `inbound_ids`（作为「额外授权」）。套餐里 `all_nodes` 为真时，就是全部入站。

迁移**不自动执行**。新增 `mpx plan suggest` 命令：把现有用户按相同的 `inbound_ids` 集合分组，列出「可以建成 N 个套餐」，加 `--apply` 才建套餐并挂上用户，同时清空这些用户的 `inbound_ids`。原来为空（全部）的用户保持不动，除非管理员明确选择挂到某个 `all_nodes` 套餐。

实现方式：store 读用户时，按 `plan_id` 解析出一个只在内存里的授权集合，不序列化。`AllowsInbound` 先看这个集合，所以各调用点签名不变。代价是 `ListUsers` 要多一次查询，把套餐表整张读进来；套餐数量是个位数到两位数，可以接受。

### 3.4 流量配额和时长：v1 不进套餐

用量和到期已经按用户存，判定也写在 `User.Status`。如果把配额放进套餐，就会出现「套餐里写 100G、用户上又改成 200G，以哪个为准」，等于给同一件事造两份事实。

**最小够用的做法**是给套餐加可选的**默认值**：`default_data_limit`、`default_days`、`default_reset_strategy`。只在「新建用户时选了这个套餐」或者 `mpx user renew --plan-defaults` 时**一次性复制**到用户身上，之后以用户自己的值为准。建议放在 P4，可以不做。v1 只做权限。

### 3.5 和分流规则的策略组怎么配合

- 不需要新增任何机制：策略组本来就是从「该用户能用的端点」里挑成员，挂了套餐以后，用户在客户端里自然只看到套餐内的节点。
- 风险是某个策略组对某个套餐来说是空的，比如「日本节点」组对「基础」套餐。现在的兜底是这个组只剩 DIRECT 并给出警告（已定案 3），但警告目前只按「全部入站」来算。
- 新增：`GET /api/routing` 的 `warnings` 按套餐再算一遍，例如「策略组『日本节点』在套餐『基础』里没有入口」。`POST /api/proxy-groups/preview` 增加可选参数 `plan`，用来预览某个套餐下这个组会收进哪些入口。
- 用户层规则不受影响。

### 3.6 API（只加不改）

| 新增 | 说明 |
| --- | --- |
| `GET/POST /api/plans`、`GET/PUT/DELETE /api/plans/{id}` | 删除时如果还有用户挂在这个套餐上，返回 409 并附上用户数；加 `?reassign=<id>` 表示先把这些用户改挂到该套餐（可以是默认套餐）；不支持摘掉 |
| `GET /api/plans/{id}/preview` | 列出这个套餐此刻能用的节点、入站、入口（用显示名），以及因为排水中或满员而暂时不在订阅里的 |
| 用户 JSON 增加 `plan_id`（omitempty） | 老客户端不带这个字段时，`PUT` 保持原值，不清空。这一点需要专门测试，因为现在 `PUT` 是整体回写 |
| `GET /api/users?plan=<id>` | 按套餐筛选用户 |
| `POST /api/proxy-groups/preview?plan=<id>` | 见 3.5 |

### 3.7 CLI

```text
mpx plan list
mpx plan add 全球 --node "🇺🇸 洛杉矶 A" --node 洛杉矶B --node 东京A --node 新加坡A
mpx plan add 基础 --node 洛杉矶A --inbound la-1/reality
mpx plan edit 全球 --add-node 新加坡A --rm-inbound la-1/ws --name 全球 Pro
mpx plan show 全球            # 节点、入站、挂了多少用户、各策略组的成员数
mpx plan rm 基础 [--reassign 全球]
mpx plan suggest [--apply]
mpx user add bob --plan 全球
mpx user edit alice --plan 基础      # 不能用 --plan "" 移出套餐
mpx user list --plan 全球
```

节点和入站沿用 v0.5.0 的名字解析（显示名、内部名、唯一前缀都能用，有歧义时报错）。CSV 增加 `plan` 列，写套餐名。

### 3.8 边界与失败模式

- **删除节点**：`plan_nodes` 级联删除；如果套餐因此变空，用户就什么都不能用。删除节点的确认框里要提示「将使 N 个套餐变空」。
- **删除套餐**：有用户挂着时拒绝，不允许悄悄把这些用户变成「全部可用」。
- **满员**：计数改为调用 `AllowsInbound`，套餐用户也会计入 `max_users`。
- **排水**：和现在一样，排水中的节点不出现在订阅里，已经下发的 clients 不受影响。
- **并发**：改套餐只影响下一轮收敛和订阅刷新，和现在改用户授权一样，不需要立即下发。

## 4. 替代方案

- **用标签代替套餐**（用户带标签，节点带标签，标签相同就能用）：灵活，但「谁能用什么」要靠推理才能看出来，而且能和分流规则的标签条件混在一起。不选。
- **直接把套餐写进 `inbound_ids`**（套餐只是批量写的工具）：不用改模型，但加了节点还是要逐个写回用户，痛点 1 依旧。不选。

## 5. Non-goals

- 不按入口授权；
- v1 不做配额和时长（只有 P4 可选的默认值）；
- 不做多套餐；
- 不做用户自助换套餐或计费。

## 7. UI 需求（给原型设计）

**风格基准：**产品静态资源在 `internal/ui/assets/`（app.css、app.js、users.js、rules.js），已有原型在 `/workspace/mpx-purpose-ui-proto/`，历史截图在 `/workspace/mpx-ui-shots/`（参考 `r5/`、`rules-proto/`）。沿用现有组件：卡片、表格、`.seg`、`.chip`、右侧抽屉、确认框、callout、空状态。示例数据用 4 个真实节点：🇺🇸 洛杉矶 A、🇺🇸 洛杉矶 B、🇯🇵 东京 A、🇸🇬 新加坡 A，每个节点 1–2 个入站（例如 Reality、Hysteria2）。

### 7.1 导航

放在「管理」组，在「用户」和「节点」之间新增「套餐」，图标沿用现有风格。

### 7.2 套餐列表 `#plans`

- **页头**：标题「套餐」；说明「决定用户能用哪些节点。挂了套餐的用户只拿得到套餐里的节点」；右上角主按钮「新建套餐」。
- **每个套餐一行或一张卡片**：
  - 名字，以及备注（如果有）；
  - 包含内容：节点显示名做成标签，比如 `🇺🇸 洛杉矶 A`。只选了部分入站的节点显示成 `🇺🇸 洛杉矶 A · 仅 Reality`。`all_nodes` 显示一个「全部节点（含以后新加的）」标签；
  - 用户数，点击跳到「用户」页并按这个套餐筛选；
  - 警告徽标（可能有多个）：「套餐为空，挂着的 N 个用户什么都用不了」（红色）、「含排水中的节点」（灰色）、「策略组『日本节点』在这个套餐里没有入口」（黄色）。
- **页面底部的提示卡**：「还有 N 个用户没挂套餐，按单独授权或全部入站使用」，配一个「整理成套餐」按钮，打开 7.5。
- **等价命令**：`mpx plan list`。

### 7.3 新建 / 编辑套餐（右侧宽抽屉）

- **字段**：
  - 名字（必填，唯一；重名时在表单里报控制面的原话）；
  - 备注；
  - 「全部节点」开关。打开后，下面的节点列表变灰并显示「包括以后新加的节点」。
- **节点列表**：每个节点一行，行首是复选框，然后是显示名、地区旗帜、状态点（运行中 / 排水中 / 连不上）。
  - 勾选节点表示包含这台节点的全部入站，并在行尾注明「含以后新加的入站」；
  - 每行可以展开，列出入站（协议，例如 Reality、Hysteria2，以及端口），可以单独勾选；
  - 一旦单独勾了入站，节点复选框显示为半选（indeterminate），行尾改成「已选 1 / 2 个入站」；
  - 入站满员时打一个「满员」标签。
- **右栏实时预览**「挂这个套餐的用户会拿到」：按节点分组列出入口名（订阅里看到的名字）。排水中或满员的条目变灰并注明原因。下方再列出每个策略组在这个套餐下有几个成员，0 个的标黄。
- **挂了多少用户**：编辑时显示「N 个用户在用」，可以展开看名单。
- **状态**：
  - 保存中，按钮显示 busy；
  - 控制面拒绝时，错误显示在抽屉底部，抽屉不关；
  - 一个节点都没勾、也没开「全部节点」时，保存按钮仍然可用，但上方出现黄色提示「空套餐：挂着的用户将无法使用任何节点」。
- **删除**：抽屉底部的危险区。没有用户时，删除只需要确认；有用户时，确认框要求选择「改挂到 [下拉选择套餐，含默认套餐]」，没有「摘掉套餐」选项。
- **等价命令**：随表单实时更新，例如 `mpx plan add 全球 --node "🇺🇸 洛杉矶 A" …` 或 `mpx plan edit …`。

### 7.4 用户页

- **列表**：原来的「可用入站」列改成「套餐」，显示套餐名标签。没有套餐的用户显示「全部入站」或「单独授权 · 2 个入站（用节点显示名）」。用户有额外授权时，在套餐名后加「+1」。
- **筛选**：增加「套餐」下拉框，选项是全部 / 各个套餐 / 未挂套餐。
- **新建或编辑用户的抽屉**：
  - 「套餐」单选下拉框，第一项是「不挂套餐」；
  - 选了套餐后，下面显示这个套餐包含的节点（只读标签）；
  - 原来的入站勾选区折叠成「额外授权（可选）」，说明「在套餐之外再给这个用户开放的入站」；
  - 不挂套餐时保持原样：入站勾选区展开，不选就是全部；
  - 节点和入站都显示成显示名加协议，不再显示 `#id`。
- **用户详情**：显示「套餐：全球（4 个节点）」，以及「实际可用」的节点列表（套餐 ∪ 额外授权）。
- **批量操作（可选）**：在用户列表里多选，然后「改挂到套餐」，对应 CLI 的批量命令。

### 7.5 「整理成套餐」向导（可选，对应 `mpx plan suggest`）

- 按相同的授权集合列出各组：「3 个用户都只能用 🇺🇸 洛杉矶 A、🇯🇵 东京 A」，每组配一个套餐名输入框（给出建议名）和「建成套餐」的勾选；
- 「全部入站」的用户单独列一组，默认不勾选；
- 确认后批量创建，结果用 toast 汇总。

### 7.6 空状态

- **一个套餐都没有**：
  - 插图，示意「套餐 → 节点 → 用户」；
  - 标题「还没有套餐」；
  - 说明「现在每个用户各自授权。把常用的几档节点组合建成套餐，以后加节点只改套餐」；
  - 两个按钮：「新建套餐」（主按钮）和「从现有用户整理」（次按钮，打开 7.5）；
  - 底部显示等价命令 `mpx plan add 基础 --node …`。
- **有套餐，但还没有用户挂上**：列表正常显示，每张卡片的用户数为 0，顶部提示「去用户页给用户选套餐」。
- **一个节点都没有**：建套餐的按钮禁用，提示「先添加节点」，并链接到节点页。

### 7.7 浅色与深色

两种主题都要出图：套餐列表（有数据和空状态各一张）、编辑抽屉（含部分入站、半选、空套餐警告）、用户编辑抽屉（选了套餐、额外授权折叠）、删除时的改挂确认框。手机宽度至少出套餐列表一张。

## 8. 未决问题（附建议）

1. **一人一套餐还是多套餐？**建议一人一套餐，加购用「额外授权」解决。
2. **套餐和单独授权同时存在时怎么算？**建议取并集，即套餐加上额外授权；另一种是套餐优先、忽略单独授权。
3. **授权粒度要不要细到入站？**建议以节点为主，入站可选；不做按入口授权。
4. **配额和时长放不放进套餐？**建议 v1 不放；P4 再做「默认值，一次性复制给用户」。
5. **空套餐是「全不可用」吗？**建议是，「全部」用 `all_nodes` 显式表达。
6. **升级时的归属**：已定案为自动创建默认套餐，规则见「已定案」一节；`mpx plan suggest` 保留为可选工具。
